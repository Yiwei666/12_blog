## 3. 机构认证流程

SAML（Security Assertion Markup Language）是一种基于 XML 的开放身份认证标准，用于在身份提供方（IdP）与服务提供方（SP）之间安全传递用户身份、认证状态和授权属性，是高校、科研机构与学术数据库实现单点登录（SSO, Single Sign-On）和机构身份认证的常用核心技术之一。

> 用户首先将机构账号密码提交给机构认证系统（IdP），由 IdP 完成身份验证；验证成功后，IdP 会生成一个短期有效的认证凭证，并用自己的私钥进行数字签名。
> 
> 浏览器再将这份临时凭证提交给数据库平台（SP），数据库使用 IdP 的公钥验证签名，并检查签发者、有效期、机构属性等信息。
> 
> 验证通过后，数据库建立自己的 Session，并授予用户相应的机构订阅访问权限；整个过程中，数据库通常不需要也看不到用户的机构账号密码。


```txt
              用户
                │
                │ 输入机构账号密码
                ▼
              机构认证系统 IdP
                │
                │ 验证账号密码
                │ 验证成功后生成临时凭证
                │ 并用 IdP 私钥签名
                ▼
              临时认证凭证
              SAML Assertion / SAMLResponse
                │
                │ 浏览器自动提交
                ▼
              数据库平台 SP
                │
                │ 使用 IdP 公钥验证签名
                │ 检查签发者、有效期、Audience、权限属性
                ▼
              认证通过
                │
                │ 建立 Session / 写入 Cookie
                ▼
              获得机构数据库访问权限
```

一个机构账号可以作为统一身份访问多个已订阅数据库，但 IdP 通常会针对每个数据库单独生成与该 SP 绑定的临时认证凭证；真正可以共享的是机构身份和 IdP 登录状态，而不是同一份 SAMLResponse 或访问 Token。机构 IdP 虽然可以给 IEEE、Elsevier、Springer Nature、Wiley 等多个数据库提供认证，但通常会针对每一个数据库分别生成新的 Assertion。


```
              第三方入口
                  ↓
              验证用户是否有权使用该服务
                  ↓
              数据库选择页面
                  │
                  ├── IEEE
                  ├── Elsevier
                  ├── Springer
                  ├── Wiley
                  └── ACS
                       ↓
              根据所选数据库
              调用对应的机构认证流程
                       ↓
              得到该数据库专用临时凭证
                       ↓
              浏览器提交给相应数据库
                       ↓
              数据库建立自己的 Session
```

## 3. 机构认证流程

### 1. 学术资源访问认证体系

**1. SAML 2.0：底层协议标准**

它不是某一家公司的认证服务，而是 IdP 与数据库 SP 之间传递认证结果和属性的标准。前面我们讨论的 SAMLResponse、Assertion、Issuer、Audience 都属于这一层。OpenAthens、Shibboleth、CARSI、InCommon 等体系都大量使用 SAML。


**2. Shibboleth：开源联邦认证软件**

可以部署 Shibboleth IdP 给学校做身份提供方，也可以部署 Shibboleth SP 给数据库或网站接收 SAML 身份。它最早来自 Internet2 项目，目前由 Shibboleth Consortium 维护，是全球科研教育领域使用最广泛的联邦身份管理软件之一。官方也明确称其为世界上部署最广泛的此类系统之一。


**3. OpenAthens：托管式学术资源 IAM + Federation**

OpenAthens 属于 Jisc，主要面向图书馆、科研机构、医疗机构和出版商。机构不想自己维护复杂的 Shibboleth 基础设施时，可以采用 OpenAthens 的云端服务。它以 SAML 2.0 为重要基础，同时还提供代理访问等能力。OpenAthens Federation 允许采用其他 SAML SSO 产品的机构加入，并不要求必须使用 OpenAthens 自己的 IdP。


**4. CARSI：中国教育科研身份联邦**

全称为“中国教育和科研计算机网联邦认证与资源共享基础设施”。高校可以用自己的校园统一身份认证账号，经 CARSI 访问参与联盟的数据库和互联网科研资源，而无需数据库单独维护一套高校账号。CARSI 基于 Shibboleth 技术并支持 SAML，是中国高校科研资源联邦认证的重要基础设施。


**5. InCommon Federation：美国科研教育身份联邦**

主要面向美国高校、研究机构及其服务提供商，由 Internet2 体系运营。Shibboleth 是 InCommon 的重要基础软件之一；InCommon 又接入 eduGAIN，因此美国高校身份可以进一步访问其他国家 Federation 中开放的服务。


**6. UK Access Management Federation：英国科研教育身份联邦**

由 Jisc 运营，也是基于 SAML 的联邦认证体系。Jisc 目前称英国超过 95% 的高等教育机构以及超过 90% 的继续教育机构使用该 Federation。它和 OpenAthens 是两个不同的东西，只是都由 Jisc 提供相关服务。


**7. eduGAIN：全球“身份联盟之间的联盟”**

eduGAIN 本身通常不直接给学生发账号，也不是另一个 IdP。它的作用是把 CARSI、InCommon、UK Federation 等各国/地区 R&E Federation 互联起来。这样数据库和高校不用彼此一对一建立几十万个信任关系。目前 eduGAIN 已连接 80 多个 Federation、数千个 IdP 和 SP。


**8. EZproxy：代理式电子资源访问系统**

这一类与 SAML 的原理明显不同。用户先通过学校账号验证，之后 EZproxy 代表用户访问数据库；数据库看到的是学校已经登记的 EZproxy IP，因此仍然可以按“机构 IP 授权”放行。EZproxy 本身又可以接入 SAML、Shibboleth、LDAP、CAS 等作为前端身份认证方式。


**9. SeamlessAccess：联邦登录的用户体验层**

很多期刊页面上看到的“Access through your institution / Select your institution”并不一定是新的身份认证协议。SeamlessAccess 主要帮助用户发现自己的机构并引导进入现有的 Federation/IdP 登录流程，本身不是替代 SAML 的认证系统。

### 2. SAML开放身份认证标准



SAML（Security Assertion Markup Language）是一种基于 XML 的开放身份认证标准，用于在身份提供方（IdP）与服务提供方（SP）之间安全传递用户身份、认证状态和授权属性，是高校、科研机构与学术数据库实现单点登录（SSO, Single Sign-On）和机构身份认证的常用核心技术之一。

> 用户首先将机构账号密码提交给机构认证系统（IdP），由 IdP 完成身份验证；验证成功后，IdP 会生成一个短期有效的认证凭证，并用自己的私钥进行数字签名。
> 
> 浏览器再将这份临时凭证提交给数据库平台（SP），数据库使用 IdP 的公钥验证签名，并检查签发者、有效期、机构属性等信息。
> 
> 验证通过后，数据库建立自己的 Session，并授予用户相应的机构订阅访问权限；整个过程中，数据库通常不需要也看不到用户的机构账号密码。


```txt
              用户
                │
                │ 输入机构账号密码
                ▼
              机构认证系统 IdP
                │
                │ 验证账号密码
                │ 验证成功后生成临时凭证
                │ 并用 IdP 私钥签名
                ▼
              临时认证凭证
              SAML Assertion / SAMLResponse
                │
                │ 浏览器自动提交
                ▼
              数据库平台 SP
                │
                │ 使用 IdP 公钥验证签名
                │ 检查签发者、有效期、Audience、权限属性
                ▼
              认证通过
                │
                │ 建立 Session / 写入 Cookie
                ▼
              获得机构数据库访问权限
```

一个机构账号可以作为统一身份访问多个已订阅数据库，但 IdP 通常会针对每个数据库单独生成与该 SP 绑定的临时认证凭证；真正可以共享的是机构身份和 IdP 登录状态，而不是同一份 SAMLResponse 或访问 Token。机构 IdP 虽然可以给 IEEE、Elsevier、Springer Nature、Wiley 等多个数据库提供认证，但通常会针对每一个数据库分别生成新的 Assertion。


```
              第三方入口
                  ↓
              验证用户是否有权使用该服务
                  ↓
              数据库选择页面
                  │
                  ├── IEEE
                  ├── Elsevier
                  ├── Springer
                  ├── Wiley
                  └── ACS
                       ↓
              根据所选数据库
              调用对应的机构认证流程
                       ↓
              得到该数据库专用临时凭证
                       ↓
              浏览器提交给相应数据库
                       ↓
              数据库建立自己的 Session
```

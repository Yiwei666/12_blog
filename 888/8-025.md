# windows系统开发环境配置

# 1. Windows 本地 PHP 8.1 测试环境部署指南

适用环境：Windows 10 / Windows 11，64 位系统。

用途：为 PHP 项目提供固定的命令行运行环境，方便语法检查、脚本测试和本地网页调试，避免临时重复下载 PHP。

## 1. 确定 PHP 版本和安装目录

本项目服务器的命令行版本为：

```text
PHP 8.1.2-1ubuntu2.28 (cli) (NTS)
```

其中 `8.1.2` 是基础 PHP 版本，`-1ubuntu2.28` 是 Ubuntu 软件包修订号，包含其维护的补丁。Windows 无需寻找相同的 Ubuntu 版本号。

本指南使用同属 PHP 8.1 系列的 Windows 版本：

```text
PHP 8.1.34
x64
Non Thread Safe（NTS）
VS16（Visual C++ 2019）
```

同属 8.1 系列更方便检查服务器的语法兼容性，但 Windows 与 Ubuntu 的补丁、扩展和系统行为并不完全相同，最终功能仍需在相应测试环境验证。

本文统一使用以下目录：

```text
D:\software\02_php\php-8.1.34-nts-Win32-vs16-x64
```

若其他电脑没有 D 盘，可以改用其他固定目录；后续的扩展路径、日志路径、PATH 和命令中的路径都需要同步修改。

> PHP 8.1 已结束上游支持。本指南将其作为现有项目的本机兼容性测试环境；新的部署应结合项目兼容性选择仍受支持的版本。

## 2. 下载 PHP 压缩包

官方入口：

- [PHP 8.1 Windows 下载页面](https://www.php.net/downloads.php?os=windows&version=8.1)
- [直接下载 PHP 8.1.34 x64 NTS ZIP](https://downloads.php.net/~windows/releases/archives/php-8.1.34-nts-Win32-vs16-x64.zip)
- [Windows 历史版本目录](https://downloads.php.net/~windows/releases/archives/)

在下载页面中选择 **VS16 x64 Non Thread Safe → Zip**。

文件名应为：

```text
php-8.1.34-nts-Win32-vs16-x64.zip
```

注意：

- 下载完整运行包，不选择源码、Debug Pack 或 Development Package。
- NTS 适用于本次命令行测试用途。
- 文件名中的 `Win32` 不表示它是 32 位版本，架构看文件名末尾的 `x64`。

## 3. 安装微软 Visual C++ 运行库

PHP 的 Windows 版本依赖 Microsoft Visual C++ 运行库。使用官方最新支持的 **v14 X64** 安装包即可兼容本指南中的 VS16 构建。

- [微软官方 X64 运行库下载](https://aka.ms/vc14/vc_redist.x64.exe)
- [微软官方说明页面](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist?view=msvc-170)

操作步骤：

1. 下载 `vc_redist.x64.exe`。
2. 双击运行。
3. Windows 询问是否允许更改设备时，点击“是”。
4. 勾选同意许可条款，点击“安装”。
5. 安装成功后点击“关闭”；如提示需要重启，按提示重启电脑。

如果显示“修复 / 卸载”，说明已安装，可以先关闭；如 PHP 后续提示运行库损坏，再选择修复。如果提示已有更新版本，保留现有版本即可。

运行库由安装程序自动配置，不需要自行选择目录或添加 PATH，也不需要安装 Visual Studio 开发工具。

## 4. 解压 PHP

把 PHP ZIP 的完整内容解压到本文约定的目录。确认 `php.exe` 直接位于该目录中，避免多套一层同名文件夹。

目录结构示例：

```text
D:\software\02_php\php-8.1.34-nts-Win32-vs16-x64\
    php.exe
    php-cgi.exe
    php.ini-development
    php.ini-production
    ext\
    其他 DLL 文件和目录……
```

保留压缩包中的全部文件，不要只复制 `php.exe`。

## 5. 创建和配置 php.ini

在 PHP 目录中，将 `php.ini-development` 复制一份，把副本命名为 `php.ini`。

完整路径为：

```text
D:\software\02_php\php-8.1.34-nts-Win32-vs16-x64\php.ini
```

在资源管理器中开启“文件扩展名”显示，确认文件没有被命名为 `php.ini.txt`。如果已有配置文件，先备份，不直接覆盖。

用记事本或 VS Code 打开 `php.ini`，搜索相应配置项，在原位置修改为以下内容。不要把这些内容重复追加到文件末尾；以分号 `;` 开头的配置是注释，需要去掉行首分号才能启用。

▶️ **扩展目录**

```ini
extension_dir = "D:/software/02_php/php-8.1.34-nts-Win32-vs16-x64/ext"
```

▶️ **启用扩展**

```ini
extension=curl
extension=mbstring
extension=mysqli
extension=openssl
extension=pdo_mysql
```

其中 `mysqli` 是本项目访问 MySQL 所需的扩展，其他扩展方便处理中文、数据库和网络请求。它们对应的 DLL 已包含在本次 Windows ZIP 的 `ext` 目录中。

▶️ **时区**

```ini
date.timezone = Asia/Shanghai
```

▶️ **本地错误显示与日志**

```ini
error_reporting = E_ALL
display_errors = On
display_startup_errors = On
log_errors = On
error_log = "D:/software/02_php/php-8.1.34-nts-Win32-vs16-x64/php_errors.log"
```

这些错误显示设置用于本地开发测试。日志文件会在有错误需要记录时创建，不要求安装后立即出现。

其余配置保留 `php.ini-development` 原值即可。保存后，命令行 PHP 会在下次运行时读取配置；已启动的本地 PHP 测试服务器需重新启动。

## 6. 添加用户 PATH 环境变量

1. 在 Windows 开始菜单中搜索“编辑账户的环境变量”。
2. 在“用户变量”中选中 `Path`，点击“编辑”。
3. 点击“新建”，添加下面的目录。
4. 保留原有其他条目，逐层点击“确定”。

```text
D:\software\02_php\php-8.1.34-nts-Win32-vs16-x64
```

添加的是目录，不是 `php.exe` 文件。

完成后关闭旧 PowerShell，重新打开一个窗口；完全退出并重新启动需要调用 PHP 的 Codex 或编辑器，让它们读取更新后的 PATH。



## 7. 验证安装

在新打开的 PowerShell 中逐条执行：

```powershell
where.exe php
php -v
php --ini
php -m
```

检查以下结果：

| 检查项 | 预期结果 |
| --- | --- |
| `where.exe php` | 找到安装目录中的 `php.exe`；若列出多个版本，确认优先使用的是本次安装 |
| `php -v` | 显示 PHP 8.1.34、NTS、x64，没有启动错误 |
| `php --ini` | `Loaded Configuration File` 指向刚创建的 `php.ini` |
| `php -m` | 包含 `mysqli`、`pdo_mysql`、`mbstring`、`curl`、`openssl` |

检查时区：

```powershell
php -r 'echo date_default_timezone_get(), PHP_EOL;'
```

预期输出：

```text
Asia/Shanghai
```

PATH 尚未生效时，可以直接通过完整路径验证，不需要重新下载 PHP：

```powershell
& "D:\software\02_php\php-8.1.34-nts-Win32-vs16-x64\php.exe" -v
& "D:\software\02_php\php-8.1.34-nts-Win32-vs16-x64\php.exe" --ini
```

PowerShell 中，带引号的可执行文件路径前要加调用运算符 `&`。


## 8. 检查项目 PHP 语法

以下使用的项目路径是示例，请改为新电脑上的实际项目目录。

```powershell
$projectDir = 'D:\projects\paperDatabases'
php -l (Join-Path $projectDir '08_web_crossRef_query.php')
php -l (Join-Path $projectDir '08_tm_batch_paper_categories.php')
```

成功时会显示：

```text
No syntax errors detected in ...
```

`php -l` 只检查语法，不执行脚本，不会连接数据库或触发论文入库、分类增删。语法检查通过，也不代表数据库操作、接口通信和业务逻辑已经验证。


## 9. 可选：启动本地网页测试服务器

在 PowerShell 中执行，项目路径按实际情况修改：

```powershell
$projectDir = 'D:\projects\paperDatabases'
php -S 127.0.0.1:8000 -t $projectDir
```

保持该窗口运行，在浏览器访问：

[本地论文检索页面](http://127.0.0.1:8000/08_web_crossRef_query.php)

结束测试时，在启动服务器的窗口按 `Ctrl+C`。

这是本机开发测试服务器，绑定地址为 `127.0.0.1`。Windows 上的 PHP 内置服务器使用单进程处理请求，不适合用来评估线上并发性能。

本项目的网页需要数据库支持；完整功能测试还需要配置对应的测试数据库。PHP 的 `mysqli` 扩展只是连接数据库的客户端扩展，并不会自动安装 MySQL 服务。

另外，当前项目中的 `API_BASE_URL` 指向线上服务器。打开本地页面，不会自动把分类接口切换到本地；做数据库功能测试前，需要核对数据库连接和接口地址，使用对应的测试配置。
